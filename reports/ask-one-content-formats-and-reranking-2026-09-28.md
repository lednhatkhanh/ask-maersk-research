# Ask ONE: broader content, OCR and reranking

**Checked:** 28 September 2026. **Use:** source check for the manager and technical slides. This records supported paths and a sensible scope boundary; it does not establish what ONE's current search indexes or approve a later multimodal rollout.

## What can be said in the manager story

Ask ONE can make **approved content from several sources useful in one answer**, instead of returning only a list of text results. The proposed POC synchronizes Drupal **Insight** content and ingests selected, owner-approved eCommerce/business guidance and documents, then returns a short answer with a source and next action. A later content roadmap can add more PDF/Word material, scanned documents and images, and eventually video-derived guidance. This is a product expansion path, not a claim that all formats work in the first two months. [RAG Engine supported documents](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/supported-documents), [RAG Engine LLM parser](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/llm-parser), [Agent Retrieval Data Objects](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/data-objects/data-objects).

**Avoid the proposed comparison “current ONE search cannot index PDFs/docs/images/video.”** The supplied search screenshot shows links to PDFs; it does not prove whether their contents are indexed. It also provides no evidence about image or video indexing. The safe distinction is that the viewed journey presents a list of text results, while Ask ONE proposes a governed, source-backed answer across approved content types. This point is based on reviewer-provided screenshots and description, not a search-platform audit.

## Practical content paths

| Content | Direct RAG Engine | Custom ingestion + Agent Retrieval | Proposal boundary |
| --- | --- | --- | --- |
| Drupal Insight HTML/text, approved FAQs | Default parser supports HTML, JSON, Markdown and text. | ONE extracts, versions and chunks approved content into Agent Retrieval Data Objects. Agent Retrieval stores searchable JSON objects; it is not a Drupal/file parser. | POC baseline. |
| PDF / Word documents | Default parser supports PDF up to 50 MB and DOCX up to 50 MB; PPTX up to 10 MB. Size and parser limits vary. | ONE parses/extracts text, attaches source/page/version metadata and writes chunks as Data Objects. | Include only a small approved document set in the POC. |
| Scanned pages and standalone images | RAG Engine's Gemini LLM parser supports PDF plus PNG, JPEG, WebP, HEIC and HEIF; Document AI OCR can extract text from scanned pages, and Layout Parser can make context-aware chunks. The LLM parser and Document AI introduce separate processing cost. | ONE may call Document AI OCR/Layout Parser or a vision model before indexing approved, reviewable text/metadata; raw files are not made searchable merely by writing a Data Object. | Demonstrate with a sample only if owners supply suitable material; broader ingestion is later scope. |
| Video | Video is **not in RAG Engine's listed default or LLM-parser file types**. | A separate preprocessing path can transcribe audio with Speech-to-Text, describe video with Gemini, or create multimodal embeddings; then index approved segments with source URL and timestamp. Google documents video-capable `gemini-embedding-2`, but the exact Agent Retrieval integration, region, cost, permissions and citation UX need a separate trial. | Roadmap opportunity, not a POC delivery claim. |

Sources for the table: [RAG Engine document types](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/supported-documents), [LLM parser types and cost](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/llm-parser), [Document AI OCR](https://docs.cloud.google.com/document-ai/docs/enterprise-document-ocr), [Document AI layout parser with RAG Engine](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/layout-parser-integration), [Agent Retrieval Data Objects](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/data-objects/data-objects), [Agent Retrieval embedding models](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/embeddings/autogenerating-embeddings), [Google Cloud video transcription tutorial](https://docs.cloud.google.com/speech-to-text/docs/v1/transcribe-audio-from-video-speech-to-text), [Vertex AI video example](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/samples/googlegenaisdk-textgen-with-video).

For all formats, content-owner approval, publication status, region/security suitability, deletion/update propagation, and usable citations remain application requirements. OCR or multimodal embeddings do not themselves prove a retrieved claim is correct. The RAG Engine Layout Parser integration also documents a 20 MB per-file limit and 500-page PDF limit, lower than the default parser's PDF limit. [Layout Parser integration](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/layout-parser-integration).

## Where reranking fits

The flow is **retrieve candidate passages → rerank against the customer's question → pass the strongest approved passages to Gemini → check citations before display**. Reranking improves the order of candidates; it does not replace source approval or answer verification. In the custom path, Agent Retrieval's VertexRanker runs after hybrid search results are fused with reciprocal rank fusion. It uses the Ranking API server-side, requires the Discovery Engine API, and can fall back to fused results with a warning for some ranker failures. In direct RAG Engine, retrieval configuration can call the Agent Platform ranking API or use a Gemini LLM reranker; Google describes the latter as slower and billed by model tokens. Reranking is a billable component in the RAG Engine path. [Agent Retrieval VertexRanker](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/query-search/reranking), [RAG Engine reranking](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/retrieval-and-ranking), [RAG Engine billing](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/rag-engine-billing).

**POC comparison:** run the same labelled questions with reranking on/off for both viable paths. Record relevant-passage recall/precision at the chosen `k`, supported-answer and citation pass rate, latency and cost. Keep the reranker if it improves the customer task without breaking the agreed latency or service-cost envelope. That is a proposed evaluation method, not a measured benefit.
