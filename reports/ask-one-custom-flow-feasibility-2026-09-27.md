# Ask ONE custom flow: component compatibility check

Checked 27 September 2026 against Google Cloud product documentation. This is a documentation feasibility check, not an executed integration test or security approval.

## Verdict

**The custom flow is technically composable for a PoC.** ONE can run ingestion and the customer API on GKE, generate and store embeddings, search approved chunks in standalone Agent Retrieval, rerank candidates, pass selected passages to Gemini, screen requests and responses with Model Armor, and check citations before release. These are separate APIs joined by ONE code, not a single managed end-to-end guarantee. The main unresolved release gate is **where integrated VertexRanker/Ranking API processes candidate text** when Agent Retrieval is in Singapore. The published Ranking API example uses a `global` ranking configuration; the Agent Retrieval integration documentation does not establish Singapore processing for its internal Ranking API call. Require Google/ONE security confirmation or an approved reranker design before promising Singapore-only processing. [Agent Retrieval overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/overview), [integrated reranking](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/query-search/reranking), [Ranking API](https://docs.cloud.google.com/generative-ai-app-builder/docs/ranking).

## Compatibility by step

| --- | --- | --- |
| GKE app and Google APIs | Workload Identity Federation lets GKE workloads call Google APIs with scoped IAM permissions. It does not grant permissions automatically. | Compatible. Configure distinct ingestion and API identities, service permissions, API enablement and egress/PSC as needed. [GKE authentication](https://docs.cloud.google.com/kubernetes-engine/docs/how-to/workload-identity), [Agent Platform VPC access](https://docs.cloud.google.com/gemini-enterprise-agent-platform/machine-learning/general/vpc-service-controls). |

ONE's plan also requires shared atomic counters across GKE replicas before paid AI work; no quota-store product has been selected. | Compatible design, **incomplete configuration**. Choose and test the shared counter store, validate challenges in the API, restrict direct origin access, and test concurrent calls and store failure. Cloudflare alone is not a spending cap. [Turnstile validation](https://developers.cloudflare.com/turnstile/get-started/server-side-validation/), [ONE usage-control plan](../PLAN.md#bot-access-and-usage-protection). |
| Cloud Storage originals and source records | Cloud Storage stores the source material; Agent Retrieval stores searchable passage payloads. | Compatible, but ONE must implement source/version IDs, approved status, idempotent publishing and a withdrawal register. [Search API](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/query-search/search), [text embeddings](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/embeddings/get-text-embeddings). |

Do not base the MVP on advanced structured text search without checking its Preview status. [Search API](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/query-search/search), [Agent Retrieval overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/overview). |

[Reranking](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/query-search/reranking), [Ranking API example with global config](https://docs.cloud.google.com/generative-ai-app-builder/docs/ranking). |
| Gemini generation and citation release | Gemini 2.5 Flash lists Singapore model availability. [Gemini 2.5 Flash](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/2-5-flash), [ONE component design](ask-one-custom-rag-component-research-2026-09-27.md#recommended-custom-default). |
| Withdrawal and replacement | Data Objects support create, update, delete and batch delete; ETags support concurrency control. | Compatible primitives, but deletion is not an instantaneous end-to-end revocation contract. Set an app-side denylist/approved-version check that blocks withdrawn IDs at answer time, then test update/delete propagation, caches, retries and races. [Data Object operations](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/data-objects/data-objects), [ETags](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/data-objects/using-etags-for-concurrency-control). |
| Model Armor → Gemini → answer checks | Model Armor has Singapore regional templates and sanitize prompt/response APIs. Singapore residency-enforced templates support Responsible AI, Sensitive Data Protection and prompt-injection/jailbreak filters, but not multilingual detection, malicious-URL filtering, image scanning or antivirus. | Compatible for the planned text flow if ONE calls the Singapore regional endpoint and enforces verdicts. If using Private Google Access or VPC Service Controls, Google's regional endpoint guidance requires a Private Service Connect endpoint to avoid certificate errors. It does not validate citations/source approval. Avoid assuming the Agent Platform *floor-setting* integration has identical residency: Google's table says Singapore floor settings do not enforce in-use/in-transit residency. [Model Armor endpoints and residency](https://docs.cloud.google.com/model-armor/data-residency), [regional features](https://docs.cloud.google.com/model-armor/feature-availability-by-region), [sanitize API](https://docs.cloud.google.com/model-armor/sanitize-prompts-responses). |

Keep local parsing for ordinary HTML/PDF and evaluate OCR only for scanned material. [Document AI regions](https://docs.cloud.google.com/document-ai/docs/regions). |
| Telemetry and answer evaluation | GKE can send operational signals to Google Cloud Observability. [GKE observability](https://docs.cloud.google.com/kubernetes-engine/docs/concepts/observability), [Gen AI evaluation regions](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/evaluation-overview), [ONE evaluation decision](ask-one-custom-rag-component-research-2026-09-27.md#evaluation-and-observability-for-the-custom-gke-app). |

## PoC gates before a production claim

1. Confirm each chosen **Gemini generation and embedding model/version** in `asia-southeast1`, its regional endpoint and data-processing terms; pin versions/dimensions. A regional Agent Retrieval collection alone does not prove every downstream model or ranker stays in Singapore. [Agent Platform locations](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/locations), [data residency](https://docs.cloud.google.com/gemini-enterprise-agent-platform/resources/data-residency).
2. Ask Google for a written location/data-path answer for Agent Retrieval's **integrated VertexRanker**, including the Ranking API call and any logs. If the requirement is strict Singapore-only processing and this cannot be established, the proposed *required* reranker is a **conditional release blocker**, although the rest of the retrieval path can still be PoC tested. [Reranking](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/query-search/reranking), [Ranking API](https://docs.cloud.google.com/generative-ai-app-builder/docs/ranking).
3. Run an end-to-end Singapore PoC: publish approved chunks, embed the same content model consistently, hybrid retrieve with eligibility filters, rerank, screen, generate, verify citations, withdraw a source while queries run, and prove no withdrawn source reaches an answer. Measure warning/fallback frequency, latency, quota, cost and quality. [Search API](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/query-search/search), [quotas](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/quotas), [reranking](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/query-search/reranking).

**Important distinction:** standalone Agent Retrieval in Singapore is the custom flow described here. RAG Engine's integration with Agent Retrieval/Vector Search 2.0 is a different architecture with its own location limits; do not infer that the RAG Engine integration is available in Singapore from standalone Agent Retrieval support. [RAG Engine integration](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/use-rag-managed-vertex-ai-vector-search).
