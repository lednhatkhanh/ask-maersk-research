# Ask ONE custom RAG: Google Cloud component research

**Checked:** 27 September 2026. **Purpose:** input to the two-path comparison in [the managed RAG report](ask-one-managed-rag-research-2026-09-27.md), not an approved architecture or regional cost quote. The recommendation below is an architectural inference from current Google Cloud documentation and the proposed Ask ONE public-content scope. It needs a paired PoC and ONE's security review.

## Recommended custom default

Build the **Ask ONE application, source-governance and answer-control logic**; use managed Google Cloud infrastructure for the rest. The recommended vector database is **standalone Agent Retrieval (formerly Vector Search 2.0)** in `asia-southeast1`, subject to the PoC and security gates. It is a managed Collection/Data Object store that holds vectors **and** passage payloads, can filter on payload fields, and supports text, semantic and hybrid search. It is distinct from the RAG Engine integration with Vector Search 2.0, which Google currently documents only for `us-central1`. This fits the user's preference for a vector database without assuming Cloud SQL is required. [Agent Retrieval overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/overview), [search](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/query-search/search), [RAG Engine integration region](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/use-rag-managed-vertex-ai-vector-search).

**Cloud SQL is a switch, not the default.** Use it if the PoC shows a relational approval/transaction workflow must share the same database with chunks, or Agent Retrieval cannot meet filtering, withdrawal, cost, latency or security requirements. Cloud SQL PostgreSQL supports vector search and conventional SQL. Keeping approved originals/version records in Cloud Storage and searchable passage payloads in Agent Retrieval may avoid a separate SQL database for the MVP, but the approval audit and recovery design must be proved; a vector database alone is not a governance system. [Cloud SQL AI overview](https://docs.cloud.google.com/sql/docs/postgres/ai-overview), [Agent Retrieval overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/overview).

## Evaluation and observability for the custom GKE app

**Recommendation:** Do not require Phoenix or Ragas in the default production stack. Keep **Cloud Logging, Cloud Monitoring and Cloud Trace** for operations; instrument Ask ONE's GKE API with OpenTelemetry spans for source eligibility, retrieval, generation, citation checks and fallback. Keep a versioned, content-owner-reviewed question set and deterministic tests for approved/withdrawn sources, expected source IDs, broken citations and service links. Human reviewers remain the authority for whether answers are useful and correct. Google's Agent Platform observability dashboards consume OpenTelemetry in Google Cloud Observability, but the described per-agent views are for deployed agents; their existence does not automatically make the custom GKE application a registered Agent Platform deployment. [Observability overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/optimize/observability/overview), [project metric baseline](ask-one-metrics-and-gcp-baseline.md).

| Capability | Custom Ask ONE decision |
| --- | --- |
| **Google evaluation, conditional PoC choice** | Trial **Gen AI Evals** against stored Ask ONE questions, generated answers, retrieved passages and reviewed references if its processing location is approved. Google's service supports rubrics and custom Python functions, with aggregate and per-case results. Its managed agent hallucination metric checks claims against *tool-use evidence*; that is useful but is not a substitute for checking a citation against the exact approved source version. Add custom checks for retrieval eligibility, withdrawal and citation/source IDs. The registered custom-code metric examples are Python, so a Node/GKE application needs an evaluation adapter/job; the service does not run Ask ONE's Node checks for free. [Gen AI evaluation overview and regions](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/evaluation-overview), [manage metrics](https://docs.cloud.google.com/gemini-enterprise-agent-platform/optimize/evaluation/manage-metrics), [view results](https://docs.cloud.google.com/gemini-enterprise-agent-platform/optimize/evaluation/view-results). |
| **Google online monitors and alerts, conditional** | Google documents scheduled sampling of Cloud Trace/Logging, scores in Cloud Monitoring, per-trace rationales and threshold alerts. However, its online-monitor setup first requires a **deployed agent** and Cloud Trace; the offline trace/session workflow explicitly requires a working **Agent Runtime** deployment. Both require an invoke-agent span and `gen_ai.client.inference.operation.details` events carrying prompts, responses, system instructions and tool definitions. This documentation does **not** establish that a standalone GKE API can be enrolled directly. Test that integration or obtain Google confirmation before putting online monitors, failure clusters or their alert templates on the delivery path. Ask ONE can still create its own Cloud Monitoring quality metrics and alerts from reviewed samples. [Online monitors](https://docs.cloud.google.com/gemini-enterprise-agent-platform/optimize/evaluation/evaluate-online), [offline prerequisites](https://docs.cloud.google.com/gemini-enterprise-agent-platform/optimize/evaluation/evaluate-offline), [quality alerts](https://docs.cloud.google.com/gemini-enterprise-agent-platform/optimize/evaluation/quality-alerts), [failure clusters](https://docs.cloud.google.com/gemini-enterprise-agent-platform/optimize/evaluation/view-results). |
| **Ragas, optional offline specialist** | Add only if Google Evals plus deterministic checks fail to expose retrieval-ranking or context-recall errors on the paired PoC. Ragas documents context precision, context recall and ID-based variants, which can use Ask ONE's stable source/chunk IDs and reviewed reference contexts. It is a library and an extra scoring pipeline, not required for production request handling. [Ragas context precision](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_precision/), [context recall](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/context_recall/). |
| **Phoenix, optional developer workspace** | Add only if engineers need its trace UI, datasets and experiments beyond Cloud Trace and the Google evaluation reports. Phoenix supports OpenTelemetry/OpenInference traces and code/LLM evaluations, but self-hosting introduces a service and SQL backend to operate. Keep the reviewed test set and OpenTelemetry instrumentation independent of that choice. [Phoenix overview](https://arize.com/docs/phoenix/), [evaluations](https://arize.com/docs/phoenix/evaluation/evals), [self-hosting](https://arize.com/docs/phoenix/self-hosting/deploying-phoenix). |

**Data and cost gate:** Google's published Gen AI evaluation service regions do **not** list `asia-southeast1`; do not send the reviewed Ask ONE cases to another location without an explicit data-handling decision. Its newer `Client.evals` interface is Preview; the older `EvalTask` interface is GA but lacks the newer adaptive rubrics. Google online monitors sample traces and cap samples per run; sampled scores are not proof that every answer passed. Capturing prompt/response/system-instruction content in traces or Model Armor sanitize logs may expose customer or internal material. Model Armor template logging can record full prompts and responses, and its Agent Platform floor-setting logging is enabled by default in the console; Google says to route logs to a compliant regional bucket before enabling logging where residency applies. Decide redaction, access, retention, sampling and sink location with ONE security before collecting such content. Price evaluation judge-model tokens, Logging/Trace/Monitoring storage and use, and required Model Armor processing; Google lists Gen AI Evals model-based charges against the underlying autorater model. [Evaluation service stages and regions](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/evaluation-overview), [online monitoring](https://docs.cloud.google.com/gemini-enterprise-agent-platform/optimize/evaluation/evaluate-online), [Model Armor logging](https://docs.cloud.google.com/model-armor/configure-logging), [Agent Platform pricing](https://cloud.google.com/products/gemini-enterprise-agent-platform/pricing).

| Cost effect | Spanner mode has a provisioned tier; Serverless orchestration is free but its vector DB is billed separately. Agent Retrieval meters ANN serving capacity and index writes, payload storage and read/write operations; embeddings and ranking are separate. Direct reads and searches have different read-operation counts. A small KNN baseline and an ANN deployment may have different fixed costs; use the regional calculator with corpus size, returned top-k, questions/month, update rate and environment count. ## Singapore GA forecast check (27 September 2026)

**Do not use Q4 2026–Q1 2027 as a committed or likely RAG Engine GA window for `asia-southeast1`.** Google's [current RAG Engine region table](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/rag-overview) labels Singapore **Preview** and publishes no promotion date. The [Vertex AI release notes](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/release-notes) date the broader RAG Engine GA announcement to **20 December 2024**; that product announcement does not override the current regional Preview label. The same notes date **Serverless mode Public Preview to 3 April 2026**, not September 2026. Google's [Serverless mode page](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/serverless-mode) currently limits that mode to `us-central1`, so its release date cannot be used as the start of a Singapore regional countdown.

Google's [general launch-stage description](https://cloud.google.com/products) says the *average* Preview lasts about six months. It does not promise a 3–6 month cycle, a regional promotion sequence, or a specific quarter for this product. The proposed October–February phases, regional infrastructure work, deprecation-driven acceleration, and Q1 2027 GA likelihood are therefore **unsupported predictions**, not findings from the cited Google documentation. The [Agent Platform release notes](https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes) also provide no Singapore RAG Engine GA announcement as of this check.

**Decision consequence:** Even if Singapore RAG Engine becomes GA by Q1 2027, that alone would not make it safe to recommend for Ask ONE. Recheck the regional launch-stage table and exact service/SLA coverage; Google's [launch-stage description](https://cloud.google.com/products) says an SLA applies at GA *where applicable*, not automatically to every capability. Confirm ONE's Preview/production policy, and separately resolve the fact that Google currently says [RAG Engine data-residency controls are unsupported](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/rag-overview). Then require the same content-withdrawal, filtering, citation/answer-quality, latency, complete-cost and security evidence as the custom path before changing the recommendation. Obtain a written regional roadmap or product commitment from Google if a dated launch dependency is needed; no public date was established by the sources checked here.

## PoC gates before making this the final default

1. Run the same permitted, versioned content and reviewed questions through RAG Engine Spanner mode and standalone Agent Retrieval; include Cloud SQL only if the approval workflow or retrieval results justify it. Compare eligible-candidate recall, answer/citation review, fallback and withdrawn-source exclusion.
2. Confirm Singapore service and model endpoints, security controls, Preview acceptance, CMEK requirements and where each optional Ranking API/Document AI call processes data. A Singapore Agent Retrieval Collection does not by itself prove Singapore-only processing for every pipeline stage.
3. Price each complete stack by month and environment: app/GKE capacity, Cloud Storage versions, database/storage/search, embeddings, Gemini generation, required reranking and screening, optional OCR/parsing, telemetry and evaluations. The current Cloud SQL estimate is a dated baseline, not a comparable quote for the other path.
4. Measure implementation critical-path work and maintain the existing pilot, release and stabilization gates. Only then propose a schedule change.
