## Findings for a management decision

1. **RAG Engine can replace much of a custom ingestion and retrieval pipeline.** It handles import, parsing, chunking, embedding orchestration, corpus indexing and retrieval. Ask ONE would still need the customer interface, approved-source publishing rules, source and service-link validation, safe fallback, security enforcement, evaluation and operations. [Google RAG Engine overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/rag-overview), [RAG output fields](https://docs.cloud.google.com/gemini-enterprise-agent-platform/reference/models/rag-output-explained).
2. **Singapore is a material deployment gate, with no published GA date.** Google lists RAG Engine in `asia-southeast1` as **Preview**. The two US GA locations require an allowlist for new projects; Frankfurt and the Netherlands are GA. API version `v1` availability does not change the regional launch stage. Google's Pre-GA terms say Preview features are provided as-is, can have limited support and can change incompatibly. A suggested **Q4 2026–Q1 2027 Singapore GA window is unsupported**, so it must not become a schedule assumption. Region, support terms and the actual security requirements need approval before using Singapore Preview for production. [Regions and launch stages](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/rag-overview), [deployment modes and Preview terms](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/deployment-modes).
3. **The recommended custom default uses a managed vector database, not Cloud SQL.** Gemini/Vertex AI can produce embeddings and answers; persistent vector retrieval is a separate choice. Standalone Agent Retrieval (formerly Vector Search 2.0) is the preferred starting point for the custom workflow because it holds vectors and payloads, supports filtered text/vector/hybrid search, and lists Singapore as a supported region. Cloud SQL PostgreSQL with `pgvector` is a fallback benchmark if Agent Retrieval fails the PoC's governance, quality, cost or security gates. A vector store does not itself approve content. [Text embeddings](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/embeddings/get-text-embeddings), [Agent Retrieval overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/overview), [Agent Retrieval search](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/query-search/search), [Cloud SQL vector support](https://docs.cloud.google.com/sql/docs/postgres/ai-overview).
4. **An eight-month implementation is a scenario, not a consequence of choosing RAG Engine.** The proposed reduction from nine months is one calendar month after the separate discovery and eight-week PoC. Relative to a Cloud SQL pipeline built in application code, RAG Engine might remove roughly **3–6 engineering weeks** of pipeline/database work (planning assumption), but integration and evidence work consume part of that time. Standalone Agent Retrieval also manages the vector database and can narrow this difference. The **0–4-week net critical-path range applies only to that older Cloud SQL comparison**; no schedule saving versus the recommended Agent Retrieval design has been measured. The eight-month milestone plan below requires a scope and readiness review; it must not turn a conditional release into a fixed commitment.
5. **The custom path needs a complete retrieval design, including a reranking decision.** Google's do-it-yourself RAG workflow places candidate retrieval before a Ranking API rerank and answer generation. Reranking is required in the proposed design; its exact managed implementation must pass regional, latency, quality and cost gates. It cannot rescue passages that candidate retrieval never found. The current two-path budget includes one reranking pass per question; reprice if candidate count or passes increase. [Google build-your-own RAG workflow](https://docs.cloud.google.com/generative-ai-app-builder/docs/builder-apis), [Ranking API](https://docs.cloud.google.com/generative-ai-app-builder/docs/ranking), [current project estimate](ask-one-gcp-cost-estimate.md).
6. **The linked Builder APIs page contains an outdated generation step.** It still offers the Grounded Generation API, but Google's dedicated page says that API is deprecated and closed to new requests. A new Ask ONE design should use a current `generateContent` path. The separate Check Grounding API remains documented and can be evaluated as an optional answer check. [Builder APIs overview](https://docs.cloud.google.com/generative-ai-app-builder/docs/builder-apis), [Grounded Generation deprecation](https://docs.cloud.google.com/generative-ai-app-builder/docs/grounded-gen), [Check Grounding](https://docs.cloud.google.com/generative-ai-app-builder/docs/check-grounding).

## Recommended two-path proposal

Present **two implementation approaches** to management: **(A) use RAG Engine directly** for ingestion and retrieval, or **(B) build the Ask ONE RAG workflow while buying managed GCP components**. The four deployment combinations in the next table are backend variants within those two approaches, not four equal proposals.

**Recommended default for the PoC and first implementation plan: B, custom workflow with standalone Agent Retrieval as the managed vector database.** This follows the preference for a vector database without making Ask ONE operate one. Keep approved content, chunk records and source IDs in a portable form so the retrieval service can be replaced. RAG Engine remains the challenger: adopt it if the same-question comparison shows a meaningful benefit and its Singapore Preview, metadata, security, lifecycle and cost limits meet the agreed requirements. This is a **project recommendation based on current documentation and design fit**, not proof that Agent Retrieval wins quality, cost or regional security review. Cloud SQL/pgvector stays a fallback benchmark if the vector service fails a required gate; it is not the default. [Agent Retrieval overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/overview), [RAG Engine regions](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/rag-overview), [Agent Retrieval search and filters](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/query-search/search).

### Evaluation and observability choice for either RAG path

**Revised default: do not provision Phoenix or make Ragas a required evaluator for the PoC.** Start with application-instrumented Cloud Trace, Cloud Logging and Cloud Monitoring, a versioned set of permitted questions and source passages, deterministic source/citation/withdrawal checks, and human answer review. Test Google's Gen AI evaluation SDK on saved Ask ONE `prompt`/`response` cases as a candidate scoring service. Google documents evaluation of existing responses and custom metrics; this can cover part of the earlier Ragas role without self-hosting an evaluation workspace. A model judge still cannot certify source approval, factual truth or customer resolution. Retain Promptfoo as a separate candidate for adversarial tests, subject to the same cost/data review. This is a **project recommendation**, not a claim that all native evaluation features are production-ready for Ask ONE. [Evaluation dataset format](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/evaluation-dataset), [managed and custom metrics](https://docs.cloud.google.com/gemini-enterprise-agent-platform/optimize/evaluation/manage-metrics), [Gen AI evaluation service](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/evaluation-overview), [current measurement baseline](ask-one-metrics-and-gcp-baseline.md).

The six linked **Agent Platform agent-observability pages do not prove a drop-in dashboard for the proposed GKE app**. Online monitors require a deployed Agent Runtime agent and Cloud Trace, plus an invoke-agent span and inference events carrying prompts, responses and system instructions. They sample traces and export scores to Cloud Logging/Monitoring; quality alerts consume those scores. The offline trace/session UI likewise requires a working Agent Runtime deployment. RAG Engine is the retrieval service in one option, not the application runtime, so neither retrieval choice alone satisfies these prerequisites. The PoC should test Agent Platform's console monitors only if ONE deliberately changes the runtime or Google confirms support for this GKE pattern. Ordinary Cloud Trace/Logging/Monitoring remain usable for the custom app with its own OpenTelemetry spans. [Online monitors and telemetry](https://docs.cloud.google.com/gemini-enterprise-agent-platform/optimize/evaluation/evaluate-online), [offline evaluation prerequisites](https://docs.cloud.google.com/gemini-enterprise-agent-platform/optimize/evaluation/evaluate-offline), [observability scope](https://docs.cloud.google.com/gemini-enterprise-agent-platform/optimize/observability/overview), [quality alerts](https://docs.cloud.google.com/gemini-enterprise-agent-platform/optimize/evaluation/quality-alerts).

**Singapore is a separate gate for managed scoring.** Google's current [Gen AI evaluation service region list](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/evaluation-overview) does **not** include `asia-southeast1`; it lists other regions and `global`. Its newer recommended `Client.evals` interface is Preview, while the older `EvalTask` interface is GA but lacks newer rubric methods. Do not send ONE questions, answer text or source passages to a non-Singapore evaluation endpoint without a documented data-handling decision. If that is not approved, keep reviewed cases and scoring in the approved environment; a small local harness or Ragas jobs are options only if they add a needed metric. Add Phoenix only if Cloud Trace plus the review record fails a demonstrated investigation need. Compare score quality, reviewer effort, data handling and service/hosting cost before adopting either. [Evaluation service regions and SDK stages](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/evaluation-overview), [dataset feature stage](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/evaluation-dataset).

**Model Armor logs are security evidence, not answer-quality evaluation.** For direct sanitize calls, use its correlation ID to link filter decisions to ONE's request trace. Audit logs are metadata, while optional sanitize-operation platform logs contain full prompts and responses and can be costly or sensitive; keep raw content logging off unless retention, access and regional routing are approved. The app still enforces the Model Armor verdict and records its own release/fallback outcome. [Model Armor logging controls and log types](https://docs.cloud.google.com/model-armor/configure-logging).

**Index publication rule for the PoC:** put only permitted current versions into the searchable collection, apply an eligibility filter during retrieval, and re-check returned source/version IDs against the authoritative published manifest before releasing an answer. Test updates, withdrawal, retries and cache invalidation end to end. These are Ask ONE design controls inferred from the documented filter and Data Object APIs, not a claim that Agent Retrieval supplies a complete content-approval workflow. [Search filters](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/query-search/search), [Data Object operations](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/data-objects/data-objects).

## Custom-built path: component audit against current GCP docs

Here “custom-built” means Ask ONE owns the pipeline and application logic while using managed Google models and, if selected, managed storage and ranking APIs. It does **not** mean training or hosting a foundation model. Google's component workflow covers parsing, embedding, vector search, **ranking** and answer generation, but its Grounded Generation API reference is outdated. **Reranking is a quality stage, not a correctness guarantee.** If relevant evidence is absent from the candidate set, reranking cannot create it. **Current generation choices for the custom retriever:** The simple baseline retrieves, optionally reranks and then sends selected passages to Gemini `generateContent`; the app maintains source IDs, verifies citations and applies the release rule. An alternative is Gemini [Grounding with your search API](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/grounding-with-your-search-api): `generateContent` can call a secured Ask ONE `POST` endpoint with `{"query":"..."}`, whose response is an array of `{"snippet":"...","uri":"..."}`. Gemini can then return retrieval queries, grounding chunks and segment-to-chunk support metadata. This is **not** automatic grounding for the application-supplied-context baseline. It lets the model decide when and how to query, and adds an API endpoint, API-key handling, latency and failure path. Test whether it preserves approved-source filtering, stable public URLs, Singapore/security requirements and the desired citation quality before choosing it. Grounding against an **Agent Search data store** is another product path; an Agent Retrieval Collection or Cloud SQL table does not automatically become such a data store. [Grounding overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/overview), [Grounding with your search API](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/grounding-with-your-search-api), [Agent Search grounding](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/grounding-with-vertex-ai-search).

**What Check Grounding adds:** The request accepts an answer candidate of at most **4,096 tokens** under this API's documented word/period counting rule and up to **200 facts of 10,000 characters each**. It returns an overall support score from 0 to 1, cited fact chunks, claim-to-citation links and optionally claim-level scores. In this version, one sentence is one claim; claim spans use **UTF-8 byte offsets**, which a citation UI must map correctly. `citationThreshold` defaults to **0.6** and controls which citations are emitted. It is **not** an Ask ONE answer-pass threshold. The overall score only loosely approximates the fraction of claims supported by supplied facts, so set any release threshold using labelled cases and human review. The guide describes a design latency under 500 ms; measure actual p50/p95 and failures rather than treating that as an SLO. Its documented quota is **300 checks/minute/project**. The examples for Check Grounding and Ranking use `locations/global`; their GA status does not establish Singapore-only processing. [Check Grounding inputs, outputs and examples](https://docs.cloud.google.com/generative-ai-app-builder/docs/check-grounding), [Agent Search quotas](https://docs.cloud.google.com/generative-ai-app-builder/quotas), [Agent Search locations](https://docs.cloud.google.com/generative-ai-app-builder/docs/locations).

## Technical scorecard and wording for a later slide revision

The supplied metrics list is a useful vocabulary, with several adjustments for Ask ONE. Keep **retrieval**, **answer correctness**, **claim support** and **service behavior** separate. A faithful answer can repeat an outdated source; a relevant answer can still be wrong; a high citation score does not approve the source. Evaluate against a versioned, human-labelled question set, with topic and answerable/unanswerable slices, sample counts and the same cases for every architecture. Treat any Google judge score, optional Ragas score or Check Grounding result as a review aid calibrated against human labels. [Google search evaluation](https://docs.cloud.google.com/gemini/enterprise/docs/evaluate-search-quality), [Google evaluation metrics](https://docs.cloud.google.com/gemini-enterprise-agent-platform/optimize/evaluation/manage-metrics), [Check Grounding](https://docs.cloud.google.com/generative-ai-app-builder/docs/check-grounding).

### Retrieval and answer quality

| Metric | Definition for the reviewed question set | Interpretation |
| --- | --- | --- |
| **Hit Rate@k** | Answerable questions with at least one labelled, sufficient approved passage in the first `k` results / answerable questions. | Shows whether retrieval found **any** usable evidence. It is not Recall@k: recall counts **all** labelled relevant items. |
| **Recall@k** | Labelled relevant approved passages found in the first `k` / all labelled relevant passages for that question; aggregate across questions and report the labelling scope. | Tests candidate coverage before reranking. If the judgement set is incomplete, call this *judged Recall@k*, not corpus-wide recall. |
| **MRR@k / nDCG@k** | MRR is the mean of `1 / rank` of each question's **first** relevant result within `k` (zero if none). nDCG compares discounted ranked relevance with the ideal order, using agreed binary or graded labels. | Use MRR when the first usable passage matters; use nDCG when several passages and their order matter. Report these both before and after reranking. Google's search evaluation docs expose recall, precision and nDCG; MRR is an Ask ONE calculation on its labelled set. [Google search evaluation](https://docs.cloud.google.com/gemini/enterprise/docs/evaluate-search-quality). |
| **Context Precision@k / evidence sufficiency** | Relevant passages in the context / all passages sent to the model; separately, questions whose supplied context contains enough approved guidance to answer / answerable questions. | Define relevance at **passage** level. A claimed “relevant-token ratio” needs token-level labels and is not interchangeable with passage precision. |
| **Correct-answer rate / faithfulness / citation precision** | Correct and complete answers / answerable reviewed cases; materially supported claims / material claims; cited material claims whose cited passage actually supports them / cited material claims. Track uncited material claims separately. | Human review is the correctness reference. Groundedness checks whether claims follow the supplied passages; citation precision checks the **specific** link or passage. Add citation recall only if reviewers have labelled which claims require citations. A Ragas faithfulness run is optional if a locally run metric is needed. [Check Grounding](https://docs.cloud.google.com/generative-ai-app-builder/docs/check-grounding), [Ragas faithfulness](https://docs.ragas.io/en/stable/concepts/metrics/available_metrics/faithfulness/). |
| **Safe fallback / over-refusal** | Correct fallback / unanswerable reviewed cases; unnecessary refusal / answerable reviewed cases. | An empty or weak retrieval result should produce an approved fallback, not a raw model answer without evidence. |

Answer relevance, semantic similarity or BERTScore can help diagnose wording, but a high similarity to one reference answer cannot by itself prove factual correctness, policy fit or citation quality. BERTScore compares contextual token embeddings between a candidate and a reference; it is not a source-verification method. Add such a metric only when it changes a review decision. [BERTScore paper](https://arxiv.org/abs/1904.09675), [Google evaluation results](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/models/eval-python-sdk/view-evaluation).

### Latency, throughput and reliability

| Metric | Measurement boundary | Reporting rule |
| --- | --- | --- |
| **Customer first-answer latency and complete-response latency** | Browser submit to first **released** answer content; browser submit to full answer **and citations**. | Report p50/p95, request counts and load level. If output is held for grounding or safety checks, a model token is not yet customer-visible. |
| **Model time to first token (TTFT)** | Model request to first generated token or first streamed chunk, according to the instrumented provider/client boundary. | Keep separate from customer first-answer latency. The latter also includes admission, query work, retrieval, reranking, network and any release checks. For chunked APIs, call it *time to first chunk* unless individual tokens are observable. [OpenTelemetry GenAI metrics](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-metrics.md). |
| **Time per output token (TPOT) / inter-token latency (ITL)** | ITL is each interval between observed output tokens; TPOT summarizes subsequent token intervals for a request. Measure only where token timing is exposed. | A stream chunk may contain several tokens; chunk interval is not automatically ITL or TPOT. Report model call duration and output-token count when token timing is unavailable. [OpenTelemetry GenAI metrics](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-metrics.md). |
| **Stage latency** | Separate spans for query preparation/embedding, candidate search, reranking, context assembly, model generation, grounding/safety checks and rendering. | Report search and reranking p50/p95 under representative corpus size and concurrency. There is no supported universal “ANN p95 under 10 ms” target for Ask ONE. |
| **Throughput and failures** | Admitted/completed questions per second (QPS), input/output tokens per second at tested concurrency, failures and timeouts / admitted requests, and rate-limit/retry counts. | QPS and token throughput describe different loads. Break down failures by retrieval, ranking, model, screening and application stage. [Google throughput sizing](https://docs.cloud.google.com/vertex-ai/generative-ai/docs/provisioned-throughput/measure-provisioned-throughput). |

### Observability, cost and index health

Use one request/trace ID from browser to generation and answer release. Record a stage span only if that stage ran, so RAG Engine and custom results remain comparable. OpenTelemetry defines GenAI call duration and token-usage conventions; OpenInference adds AI-specific span kinds such as `RETRIEVER`, `RERANKER`, `LLM` and `GUARDRAIL`. Choose a consistent mapping, not two unrelated trace trees. Record model/backend/version, source and index version, top-`k`, candidate count, optional reranker/check result, fallback reason and **trace coverage = traced admitted requests / admitted requests**. Do not export raw prompts, retrieved passages or personal data to traces by default; use IDs or redaction and apply the agreed retention policy. [OpenTelemetry GenAI metrics](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-metrics.md), [OpenInference specification](https://arize-ai.github.io/openinference/spec/), [OpenTelemetry sensitive-content warning](https://opentelemetry.io/docs/specs/semconv/registry/attributes/gen-ai/).

Track **input and output tokens per question**, identifying any cached-input subset and its actual billed rate rather than counting it twice. Add fixed database/serving charges, retrieval reads, ranking/check calls and evaluation traffic. Reconcile usage with the billing export before reporting **monthly service cost / admitted legitimate questions**. Cache hit rate is relevant only if Ask ONE actually introduces a cache; report exact, semantic and provider prompt caches separately because they have different correctness and invalidation risks. User ratings and service-link clicks are diagnostic signals, not answer-correctness labels. [OpenTelemetry GenAI token-usage metric](https://github.com/open-telemetry/semantic-conventions-genai/blob/main/docs/gen-ai/gen-ai-metrics.md), [RAG billing](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/rag-engine-billing).

For ingestion, record **source-update-to-searchable lag**, **withdrawal-to-exclusion lag**, import success/failure counts, orphan chunks, chunk-length distribution and embedding model/dimension consistency between indexed passages and queries. Version/source provenance must survive re-imports. A source being removed from the original site is not evidence it has left retrieval or an application cache; test both. [RAG Engine ingestion](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/use-data-ingestion), [Agent Retrieval Data Objects](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/vector-search-2/data-objects/data-objects).

### Security and safety

Measure successful **direct and source-borne prompt-injection attempts / labelled attempts**, benign questions falsely blocked / benign tested, confirmed personal or secret data exposures / reviewed requests, and unauthorized or withdrawn-source exposures. Report automated sensitive-data **findings** separately from confirmed exposures. Preserve the separate outcomes *detected*, *blocked* and *reached the answer*: a detection count is not an attack-success rate. For Ask ONE's public-content MVP, approved-publication and withdrawal checks are primary; per-user ACL leakage becomes a required metric if restricted content is added. If a vector filter enforces eligibility, test it **before** retrieval and after updates; post-filtering alone can leave too few useful candidates. Record corpus source/version hashes and unauthorized changes as data-integrity evidence. Model Armor and similar filters support these checks but do not replace source approval or an application release rule. [Model Armor overview](https://docs.cloud.google.com/model-armor/overview), [RAG Engine metadata filtering limits](https://docs.cloud.google.com/gemini-enterprise-agent-platform/build/rag-engine/use-metadata-search).

The two example metric slides are dense because each cell explains collection mechanics. For a future slide revision, use titles that state the point: **“Review answers against approved evidence”** and **“Measure the response customers see and the cost to run it.”** Short visible labels can be **Evidence found**, **Correct answer and source**, **Safe fallback**, **Response p50/p95**, **Failed requests** and **Service cost/question**. Keep detailed denominators and tools in notes or the technical appendix. An icon-led flow could show **approved source → retrieved passage → checked answer → service link**, with a small test-result strip; avoid replacing measurable definitions with icons alone. This is wording guidance, not a slide change.
