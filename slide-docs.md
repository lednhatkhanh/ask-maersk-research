The local deck has **20 slides**. Slide 1 restores the pink proposal cover. Slides 2–11 make the manager case, with the evidence and digital-copilot opportunity ahead of the UX, expected benefits and POC plan. Starting inputs and staffing lead to the success gate at the end of that section. Slide 9 requests an in-principle two-month POC endorsement, with staffing and access to confirm before kickoff. Slides 16–20 show repeatable evaluation, applied security, observation and the technical feedback requested.

The POC and first MVP share a single-turn, English-only interaction using approved public content. Each new question is a separate request. The POC provides read-only public guidance and navigation; it does not access accounts or submit transactions. Its evidence comes from QA and business reviewers, not customer feedback. The interface sample is a proposal, not an existing ONE product or policy. No full implementation schedule, production launch, savings or ROI is claimed.

Before the formal run, agree a versioned case sheet with the question, approved source/version, expected facts and cited passage, correct action, fallback, market, severity and reviewer. Use the same cases on both technical paths. Rerun them after approved content, prompt, model, code or retrieval changes; an existing CI runner or manual script is sufficient, with Cloud Build optional. Promptfoo probes direct requests and an isolated poisoned-source corpus. QA checks each answer beside its source, names a confirmed failure cause, assigns a fix, adds a regression case and reruns. QA and business reviewers compare representative customer tasks with current search/help. Agree pass values before measuring. The four-part exit gate supports a next-stage plan when the evidence passes.
